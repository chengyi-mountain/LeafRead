# LeafRead · 一片叶子的阅读器

> 一个**零依赖、纯离线**的网页阅读器：下载 `reader.html`，双击就能读书。
> 不用装软件、不用起服务器、不上传任何数据 —— 书和笔记都留在你自己的电脑/手机里。

**在线体验**：https://chengyi-mountain.github.io/LeafRead/reader.html


> 分享链接请用 `https://` 开头：微信打开 `http://` 链接会先弹「该页面采用未加密的 HTTP 协议」拦截页，点“继续访问”可进入，但用 https 链接不会有这一层。

## ✨ 为什么是 LeafRead

- 🍃 **极小主文件** — 主程序 `reader.html` 约 **250 KB**，两本长篇内置书放在 `books/` 目录里**点开才下载**，首屏不再等 1.5 MB
- 📴 **完全离线可用** — 运行期不请求任何外部服务；内置书一旦加载过就留在本机，断网、飞机上都能读
- 🗂️ **进度和笔记在自己手里** — 只写浏览器 localStorage，可一键导出/恢复备份，不经过任何服务器
- 📱 **手机、平板、电脑同一套界面** — 自适应布局，手机上左右点击翻页、中间点击唤出顶栏

## 📥 导入自己的书（本地文件，不经服务器）

书架页顶部有两个按钮：

| 按钮 | 用途 |
|---|---|
| **导入本地文件** | 唤起手机/电脑的文件选择器，可**多选**。TXT、EPUB、Word、PPT、Excel、Markdown、HTML、FB2、CBZ 等都能直接选，解析全在本机完成，文件不会上传到任何服务器 |
| **粘贴正文** | 没有文件、只有一段文字时用；首行可写成书名，正文里像「第X章」「Chapter N」的行会自动分章 |

「拓展书库」里点某本外部书目时，也会弹同样的三选一：**从手机选文件 / 粘贴正文 / 从网址导入**。

**中文 TXT 的编码是自动识别的**：带 BOM 的 UTF-8、不带 BOM 的 UTF-16，以及 GBK / GB18030（番茄小说、TXT 下载站常见的编码）都能正确解码，不会再出现满屏方块或「锟斤拷」式乱码。

**大文件也能导入**：正文存进浏览器的 IndexedDB，只有书名、封面、章节数这类元信息留在 localStorage（后者通常只有 5 MB 配额，装不下整本小说）。实测 8.6 MB 的中文 TXT 能完整导入并打开，导入后 localStorage 占用仍不到 1 KB。

> 关于「从网址导入」：静态网页没有后端，浏览器同源策略（CORS）会挡掉大多数第三方站点的正文抓取，所以它会经常失败。**本地文件导入是更可靠的方式**。

## 🔍 搜索范围（重要）

书架搜索框只搜**你本机书库里的书**（内置 4 本 + 你自己导入的），不会去全网检索——原因是本页面没有服务器，浏览器也不允许它直接抓取别人的网站。

当本机搜不到时，页面会在空状态下方直接给出四个公开入口，点一下就带着关键词跳过去：
古腾堡公版书库、豆瓣读书、微信读书、必应。

## 📥 导入格式

| 格式 | 状态 | 说明 |
|---|---|---|
| TXT / Markdown | ✅ | 自动按空行与“第 X 章”标题切分章节；TXT 自动识别 UTF-8 / UTF-16 / GBK 编码 |
| HTML / HTM | ✅ | 自动剥离标签、提取正文 |
| EPUB | ✅ | 内置原生 ZIP 解压；**按书自带的目录（NCX / EPUB3 nav）分章并沿用目录标题**，同一章下的多个小文件自动合并，不会再出现"一页一个目录标题"；没有目录的书才退回按 spine 顺序分章 |
| DOCX | ✅ | 读取 `word/document.xml` 正文段落 |
| PPTX / XLSX / ODT / ODP / ODS | ✅ | 分别按幻灯片、工作表、ODF 正文提取文本 |
| CBZ | ✅ | 漫画压缩包，逐页图片浏览（图片按 dataURL 存进 IndexedDB，关掉页面再打开也还在） |
| PDF（原页） | ✅ | **默认就像手机上的 PDF 阅读器**：逐页显示原书版面，扫描件、影印本、带页眉页脚和脚注的书都是原样。普通 PDF 用自带的 pdf.js 按**屏幕真实像素**（最高 3 倍）绘制，小字不发虚、打开也快；只有「字体没内嵌、字体名是 GBK 字节」的老中文 PDF 才切到 MuPDF 兼容引擎（`mupdf/`，约 10 MB，只在这类书上才下载，且带 90 秒超时兜底）。设置里「老 PDF 兼容引擎」可手动强制切换 |
| PDF（文字） | ✅ | 设置里打开「PDF 按文字阅读」后改为抽取文字层重排，可搜索、可划词、可调字号；中文老书常见的「GBK 字节塞进 ToUnicode」会自动按 GB18030 还原 |
| JPG / PNG / WEBP / GIF / BMP | ✅ | 单张图片当作一本书打开（扫描页、手写稿、长图都行） |
| RTF | ✅ | 支持 `\uN` 与 `\'hh` 两种中文转义，按 `\ansicpg` 决定码页 |
| FB2 | ✅ | FictionBook XML，按 section 分章 |
| CBR（RAR 漫画） | ❌ | 请转换为 CBZ |
| MOBI / AZW3 | ⚠️ 部分 | 二进制/加密格式，只能尽力提取可读文本 |
| 网址抓取 | ✅ | 粘贴文章 URL，自动提取正文（需要联网） |

> 解压 EPUB / DOCX / CBZ 用的是浏览器原生 `DecompressionStream`，**没有任何在线依赖**。PDF 用到两个都放在仓库里自托管的引擎：`pdf/`（pdf.js，导入时统计页数、抽文字层）和 `mupdf/`（MuPDF WASM，逐页渲染原书版面）。**两个都按需加载**，不打开 PDF 就不会下载，所以首屏仍然只有一个 250 KB 的主文件。

### 为什么 PDF 有两个引擎

仓库最早接的是 pdf.js，后来遇到一类很常见的中文老 PDF（字体名是 GBK 编码、字体文件又没内嵌，例如 1991 年版《毛泽东选集》第一卷）：pdf.js 会把整页文字画成乱码，它读到的文字层本身也是 `¹ØÓÚ¾ÀÕý` 这种 GBK 字节。同一份文件用 MuPDF 渲染则完全正常。所以：

- **原页阅读**走 MuPDF，逐页渲染成图片，版面、字体、页眉页脚都对；
- **文字阅读**走 pdf.js + 一层 GB18030 转码兜底，抽不到可用文字时会直接提示你去关掉「PDF 按文字阅读」；
- MuPDF 万一加载失败（断网、文件缺失），会自动退回 pdf.js 渲染，并在页面上写明原因，不会白屏。

**导入后会做乱码质检**：如果某个文件抽出来的文字里可疑字符比例过高（如扫描版 PDF、缺字符映射的字体），页面会提示「文字层可能不完整，换个源再试」，而不是让你打开一本书对着乱码看。

**方式一：在线体验**（推荐先点开看看）
打开 <https://chengyi-mountain.github.io/LeafRead/reader.html>

**方式二：本地使用**
1. 下载 `reader.html`（想读《德古拉》《白鲸记》的话，把 `books/` 目录一起下载下来，和它放在同一层）

## 🧱 技术构成

- 纯 HTML / CSS / JavaScript（ES6+），零第三方库、零构建步骤
- 分页用 CSS 多列（`column-width` + `scrollWidth` 计算页数），`transform` 整页平移
- 数据持久化：localStorage（`reader_state_v2`、`reader_settings_v2`、`reader_bookmarks_v2`、`reader_highlights_v2`、`reader_notes_v2`、`reader_stats_v2` …）；**导入书籍的正文走 IndexedDB**（`leafread_books_v1`），localStorage 只留元信息
- 文件解析：`DecompressionStream` 原生解压 + 正则提取 XML/HTML 文本；TXT 用 BOM 检测 + 严格 UTF-8 试解 + GB18030 回退的编码识别
- 目录分批渲染：一次 300 章，几千章的大书也不会卡
- 无障碍与移动端：触摸手势、点击热区、安全区适配

## 🐞 已知限制

- **扫描版 PDF 能看但不能搜**：原页模式会把扫描页原样显示出来，可逐页翻；但里面没有文字层，所以全文搜索、划词、TTS 都用不了（要文字得先外部 OCR）
- **PDF 原页模式首次打开要先下载排版引擎**（`mupdf/` 约 10 MB，浏览器会缓存下来，之后再用不再下载）；打开一本书后翻页是即时的，实测 352 页的书每页渲染约 0.3 秒
- CBR 是 RAR 压缩包、加密 MOBI 是 DRM 容器，均不支持，只能抽到碎片
- 内置英文公版书正文在个别位置存在**单词间空格丢失**（原始文本换行拼接遗留），属内容数据问题而非解析缺陷
- 《德古拉》《白鲸记》存放在 `books/` 目录，本地只拷 `reader.html` 时无法打开这两本
- 搜索只覆盖本机书库，不做全网检索（无后端 + CORS 限制，见上文「搜索范围」节）
- 导入书的正文存在 IndexedDB 里，所以「备份导出」的 JSON **不含导入书的正文**（只有元信息），换设备请重新导入原文件
- iOS Safari 的存储配额比桌面浏览器小，单本超过约 100 MB 的文件仍可能存不下（正常小说远小于此）；浏览器「清除网站数据」会把导入的书和阅读进度一起清掉
- 阅读数据存在浏览器本地，换浏览器 / 清缓存会丢失，重要数据请用「备份导出」留存
- 微信内置浏览器内核较旧，若打开后白屏，请点右上角「…」→ 在浏览器打开
